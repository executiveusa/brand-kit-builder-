# apps/web — human design office

## Job
Give a person one calm place to tell the studio what should exist, inspect proof, make consequential decisions, and take the finished intelligence/assets with them.

## Inputs
- Current project identity/status.
- Capability map derived from verified backend/runtime truth.
- Current stage context packet.
- Pending human gates.
- Artifact/evidence index.

## Process
1. Start from desired outcome, not product navigation.
2. Ask only for missing context.
3. Keep technology behind progressive disclosure.
4. Show proof and artifacts before explanatory feature lists.
5. Surface only decisions that require the human.
6. Preserve escape routes, history, and portable export.

## Outputs
- normalized outcome request;
- approval/rejection decisions;
- artifact review feedback;
- portable-export request;
- plain-language status view.

## Human check
The person should understand in five seconds:
- what this studio makes;
- where to ask for something;
- what the studio is doing;
- what needs their decision;
- where the proof/output is.

## Interface rules
- Popebot-style conversation is the primary surface.
- Proof-first, editorial, full-bleed work presentation; avoid dashboard-card wallpaper.
- No fake capability states.
- No model picker or agent roster in the primary journey.
- Mobile and keyboard are first-class.
- Reduced motion is mandatory.
- EN/es-MX architecture-ready; additional locales come from project requirements.

## Current artifact
`homepage-prototype.html` is a self-contained visual/product prototype. Its composer is deterministic local demo behavior and is explicitly labeled as such. It does not claim runtime agent execution.
